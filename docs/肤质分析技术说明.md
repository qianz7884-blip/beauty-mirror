# Beauty Mirror 面部肤质分析技术说明

## —— 基于 MediaPipe Face Mesh 与 ROI 分区特征提取

---

## 一、什么是 ROI，为什么美妆镜项目需要 ROI 分区分析

### 1.1 概念

**ROI（Region of Interest，感兴趣区域）** 指从完整图像中裁剪出的局部子区域。在本项目中，ROI 是指从用户面部照片中按解剖学位置划分出的独立皮肤区域。

### 1.2 为什么要分区

人脸的皮肤状态天然具有**空间异质性**：

- **T 区**（前额 + 鼻子）皮脂腺密集，容易出现油光和毛孔粗大问题
- **面颊**（苹果肌区域）角质层较薄，容易出现干燥、泛红
- **眼周**皮肤最薄（约 0.5mm），容易出现黑眼圈和细纹
- **下巴和唇周**容易因激素波动出现色素沉着或痘痘

如果只用全脸平均数据，T 区的油光和面颊的干燥会在数值上互相抵消，得出"中性、正常"的误导性结论。**分区分析**能精确定位问题到具体区域，让 AI 给出"鼻翼两侧多按压保湿产品"而非泛泛的"注意保湿"。

## 三、ROI 区域的生成方式

本项目采用**矩形包围盒（Bounding Box）裁剪**，而非多边形蒙版。

> 代码位置：[`backend/face_regions.py`](backend/face_regions.py) 第 100–204 行 `extract_region_roi()`

### 3.1 生成流程

```
步骤 1: 遍历区域内地标 → 找到 min(x), max(x), min(y), max(y)
步骤 2: 归一化坐标 (0~1) → 像素坐标 (× 图像宽高)
步骤 3: 外扩 padding（默认 15%）
步骤 4: 特殊区域额外扩展（眼周向下 20%，唇周向外 10%）
步骤 5: PIL Image.crop() 矩形裁剪
步骤 6: 限制最大边长（默认 180px，控制纹理计算耗时）
步骤 7: 输出 JPEG bytes
```

### 3.2 为什么用矩形包围盒而非多边形

| 方案 | 优势 | 劣势 |
|------|------|------|
| **矩形包围盒（本项目）** | 实现简单、计算量小、覆盖面积大 | 会混入少量非目标区域皮肤 |
| 多边形 Mask | 精确限定目标区域 | 计算复杂、边界锯齿、小区域内像素不足会导致 GLCM 纹理统计失效 |

本项目选择矩形包围盒的核心原因：ROI 仅用于**本地数值特征提取**（颜色统计、纹理分析、毛孔检测），而非展示给用户。少量边界噪声对统计结果影响极小，但精确 Mask 会显著增加复杂度且对纹理分析（GLCM 需要足够像素数）不利。

### 3.3 人脸轮廓 Mask（特殊用途）

虽然 ROI 是用矩形裁剪的，但**热力图**需要精确的人脸形状。本项目另外实现了基于 **Face Oval（人脸外轮廓）** 的多边形蒙版：

> 代码位置：[`backend/face_regions.py`](backend/face_regions.py) 第 240–313 行

- `FACE_OVAL_INDICES`（第 240–244 行）：36 个沿面部外轮廓分布的地标点
- `generate_face_mask()`（第 270–313 行）：PIL 绘制填充多边形 → numpy 浮点蒙版 → 高斯羽化边缘 → 用于热力图背景裁切

## 四、本项目提取的图像特征

> 代码位置：[`backend/feature_extractor.py`](backend/feature_extractor.py)

本项目从每个 ROI 图像中提取 **5 大类特征**，全部使用 **纯 numpy/scipy/PIL 实现**，无 OpenCV 依赖。

### 4.1 颜色特征（Color Features）

| 特征 | 计算方法 | 生理意义 |
|------|----------|----------|
| Lab 均值 / 标准差 | sRGB → CIE Lab 色彩空间转换（D65 白点） | L\* 反映皮肤亮度（水润/暗沉），a\* 反映红绿色调 |
| HSV 均值 / 标准差 | RGB → HSV 直接矩阵运算 | V 通道反映光泽度 |
| **红斑指数** | `erythema = max(0, a*_mean) / 128`，归一化到 [0,1] | 衡量面部泛红程度，敏感性皮肤判断依据 |
| **黑色素估计** | `melanin = (1 - L_mean/255) × (1 + b*_mean/128)` | 评估色素沉着、暗沉程度 |

### 4.2 纹理特征（Texture Features — GLCM）

使用**灰度共生矩阵（GLCM）** 进行纹理分析：

- 灰度量化：256 级 → 16 级
- 距离：1, 2 像素
- 角度：0°, 45°, 90°, 135°
- 对称化 + 归一化后取全方向平均

| Haralick 特征 | 公式 | 肤况关联 |
|---------------|------|----------|
| **Contrast（对比度）** | Σ(i-j)² × P(i,j) | 纹理起伏越大，对比度越高 |
| **Homogeneity（同质性）** | Σ P(i,j) / (1+(i-j)²) | 皮肤越光滑，同质性越高 |
| **Energy（能量）** | Σ P(i,j)² | 纹理越均匀（毛孔细小），能量越高 |
| **Correlation（相关性）** | Σ (i-μi)(j-μj)P(i,j) / (σiσj) | 纹理方向性，非定向皮肤纹理则接近 0 |

此外还计算**灰度直方图熵**和**复合粗糙度**（contrast × 0.35 + (1-homogeneity) × 0.35 + entropy × 0.30）。

### 4.3 毛孔特征（Pore Features）

| 特征 | 计算方法 | 含义 |
|------|----------|------|
| **高频分量比 (HF Ratio)** | Sobel 梯度 → 边缘像素（梯度 > μ+σ）占比 | 毛孔、细纹等微观纹理的密集程度 |
| **毛孔可见度** | `0.5 × HF_ratio + 0.5 × local_variance_norm` | 综合指标，越高说明毛孔越明显 |

### 4.4 斑点/色素特征（Spot Features）

| 特征 | 计算方法 | 含义 |
|------|----------|------|
| **斑点数量** | 背景估计（大核均值滤波）→ 暗斑检测（detail < -1.5σ）→ 形态学清理（3~200 px 连通域） | 痘印、色斑、痣的数量 |
| **斑点密度** | spot_count / total_pixels | 单位面积色素沉着密度 |
| **颜色方差** | Lab L\* 通道标准差 / 100 | 肤色均匀程度的量化指标 |

### 4.5 光泽/油光特征（Shine Features）

| 特征 | 计算方法 | 含义 |
|------|----------|------|
| **镜面高光比** | HSV 空间：S < 0.12 且 V > 0.78 的像素占比 | T 区油光、鼻翼高光的定量评估 |
| **光泽度评分** | `0.6 × specular_ratio + 0.4 × V_mean` | 综合光泽指标 |

## 五、特征如何转化为肤况判断和护肤建议

### 5.1 特征 → 0–100 评分

> 代码位置：[`backend/feature_extractor.py`](backend/feature_extractor.py) 第 517–595 行

使用 **Sigmoid 函数**将原始特征值映射到 0–100 分：

```
score = 100 / (1 + e^((-steepness) × (value - midpoint)))
```

- `midpoint = (low_thresh + high_thresh) / 2`：50 分对应点
- `steepness = 10 / (high_thresh - low_thresh)`：过渡区宽度

评分维度及其原始特征来源：

| 评分维度 | 主要特征来源 | 阈值逻辑 |
|----------|-------------|----------|
| **水润度 (Hydration)** | Lab L\* 亮度 | L > 130 → 高分；纹理 > 0.3 → 惩罚分 |
| **光滑度 (Smoothness)** | GLCM 同质性 | homogeneity > 0.55 → 高分；毛孔 > 0.3 → 惩罚分 |
| **光泽度 (Brightness)** | Lab L\* 亮度 | L > 130 → 高分；油光 > 0.5 → 惩罚分 |
| **毛孔细腻度 (Pores)** | 毛孔可见度 | 可见度低 → 高分（反比映射） |
| **均匀度 (Evenness)** | Lab L\* 标准差 + 斑点密度 | 低方差 + 少斑点 → 高分 |

### 5.2 评分 → 肤质分类

> 代码位置：[`backend/feature_extractor.py`](backend/feature_extractor.py) 第 625–677 行

基于**规则树**的肤质分类（不依赖 AI）：

```
输入：T 区（前额+鼻子）毛孔/油光 + 面颊粗糙度/亮度/红斑 + 眼周红斑
     ↓
判断路径：
  1. 面颊红斑 > 0.25 或眼周红斑 > 0.22 → "敏感性"
  2. T 区毛孔 > 0.45 且油光 > 0.40 → 跳步骤 3，否则跳步骤 4
  3. 面颊粗糙 > 0.35 且亮度 < 155 → "混合性"，否则 "油性"
  4. 面颊粗糙 > 0.35 且亮度 < 155 → "干性"，否则 "中性"
```

### 5.3 全脸加权评分

> 代码位置：[`backend/feature_extractor.py`](backend/feature_extractor.py) 第 597–619 行

不同维度对不同区域赋予不同权重。例如：

- **水润度**：面颊各 20%，因为面颊最能反映整体水润状态
- **毛孔**：鼻子 25% + 前额 22%，因为 T 区毛孔最明显
- **均匀度**：全区域相对均衡，眼周和唇周权重略低

### 5.4 特征 → Gemini NLG

> 代码位置：[`backend/skin_roi_prompt.py`](backend/skin_roi_prompt.py) + [`backend/skin_analyzer.py`](backend/skin_analyzer.py) 第 534–603 行

特征数据经过两级转化后传递给 Gemini：

**第一级（特征 → 自然语言描述）**：`skin_roi_prompt.py` 将数值特征转为中文描述：

| 特征 | 数值范围 | 自然语言 |
|------|---------|---------|
| brightness | < 0.42 | "亮度偏低" |
| redness | 0.16–0.26 | "泛红略明显" |
| texture | < 0.18 | "纹理较平滑" |
| shine | > 0.58 | "油光较明显" |

**示例输出**：

```
额头：亮度中等，油光轻微，泛红较低
鼻子：亮度中等，油光轻微偏高，泛红较低，存在轻微局部不稳定倾向
左脸颊：纹理轻微起伏，肤色轻微不均，泛红较低
右脸颊：纹理轻微起伏，肤色轻微不均，泛红较低
眼周：亮度中等，有轻微暗沉，肤色较均匀
下巴：亮度中等，油光较低，泛红较低
整体判断：T区油光轻微偏高，两颊状态相对平稳，泛红整体较低
```

**第二级（自然语言 → Gemini Prompt）**：将这些描述注入精心设计的 Prompt：

```
你是一位温柔、专业的护肤陪伴顾问，叫 Mirror Mate。

以下是系统通过 MediaPipe Face Mesh 和 ROI 图像特征提取得到的肤质分析结果，
请你优先基于这些结构化结果生成妆前护理建议，不要声称自己直接诊断了图片。

【机器视觉分析结果】
- 额头：亮度中等，油光轻微，泛红较低
- 鼻子：亮度中等，油光轻微偏高...
...

【重要原则】
- 绝对不要输出任何数字分数
- 不要用"好/坏"评价
- 语气像朋友聊天
- 建议要具体、可执行
```

**第三级（返回结果）**：Gemini 返回结构化 JSON，包含 `summary`（温暖护肤总结）、`recommendations`（具体建议）、`mirror_advice`（镜前即时动作，含 region/product/action/reason）。

### 5.5 特征 → 热力图

> 代码位置：[`backend/heatmap_generator.py`](backend/heatmap_generator.py)

区域评分通过**高斯扩散**生成连续热场：
1. 以各 ROI 中心为热源，构建二维热源图
2. `scipy.ndimage.gaussian_filter` 扩散成连续分布
3. MediaPipe 人脸轮廓 Mask 裁切背景
4. RdYlGn_r 科学配色映射（绿=好 → 黄 → 橙 → 红=需关注）
5. 原图 + 热力图透明叠加（alpha=0.5）

### 5.6 完整分析管线总览

```
拍照 → MediaPipe 478 点检测 → 8 区域 ROI 裁剪
     → 每区域提取 5 类特征（颜色/纹理/毛孔/斑点/光泽）
     → 逐区域 Sigmoid 评分（0-100，5 维度）
     → 全脸加权评分 + 规则树肤质分类 + 问题检测
     → [本地 RAG 皮肤科知识检索]
     → Gemini NLG 生成自然语言建议
     → matplotlib 热力图渲染
     → 返回完整结果 JSON
```

## 六、当前方法的局限

| 局限 | 具体影响 | 代码证据 |
|------|---------|---------|
| **光照敏感** | Lab/HSV 颜色特征直接受环境光影响，同一人在不同光线下可能得到截然不同的亮度和红斑指数 | `feature_extractor.py` L80-92：L\* 直接使用 RGB→XYZ→Lab，无光照校正 |
| **姿态敏感** | 侧面、仰头、低头会导致地标位置偏移，ROI 裁剪区域与预期偏离 | `face_regions.py` L131-140：仅取 min/max 包围盒，无姿态归一化 |
| **矩形包围盒不够精细** | 前额 ROI 可能包含部分头发，脸颊 ROI 可能混入少量耳朵或背景 | `face_regions.py` L169：`img.crop()` 矩形裁剪 |
| **降级绕过特征提取** | 当 ROI 提取耗时超过 `ROI_FEATURE_BUDGET_MS`（默认 500ms）时，直接返回全 50 分的默认值，跳过实际分析 | `skin_analyzer.py` L460-464：超时则 `feature_json = extractor._make_default_result()` |
| **Gemini 降级** | 当 Gemini API 不可用时，使用硬编码规则生成 fallback 建议，建议质量下降 | `skin_analyzer.py` L847-915：`_fallback_*` 系列函数 |
| **GLCM 量化损失** | 灰度 256 → 16 级量化导致纹理细节丢失 | `feature_extractor.py` L284：`gray_q = np.floor(gray / 255.0 * 15)` |
| **单图分析，无时序对比** | 每次分析独立，无法利用历史数据做趋势判断（降级模式下 `has_history: false`） | `skin_analyzer.py` L747：`'has_history': False` |
| **仅作护肤参考，非医学诊断** | Prompt 中明确要求"不要做医学诊断"，输出限制在妆前护理建议范围内 | `skin_analyzer.py` L543-551：Prompt 约束 |
| **依赖外部 API** | Gemini 调用受限于网络、API Key 有效性、速率限制 | `skin_analyzer.py` L504-507：API Key 检查 |

## 七、后续优化方向

### 7.1 光照校正

在提取颜色特征前，对图像进行**白平衡校正**或**直方图均衡化**。可使用灰度世界假设（Gray World）或基于脸部参考色卡的颜色校正矩阵。

### 7.2 ROI 边界优化

将矩形包围盒升级为**带边缘羽化的不规则多边形 Mask**，精确限定皮肤区域。可在 Polygon Mask 边缘使用 `scipy.ndimage.gaussian_filter` 做 3–5px 羽化过渡，减少边界不连续性。同时针对 T 区、面颊等区域设置更合理的 ROI 形状（例如椭圆近似），避免矩形裁剪混入头发、衣物背景。

### 7.3 姿态归一化

利用 MediaPipe 的 3D 地标（`landmarks[i].z`）进行**头部姿态估计**，对侧脸或非正脸图像进行透视校正，或将姿态信息纳入特征提取流程中做补偿。

### 7.4 可视化增强

在热力图基础上增加：
- 每区域的特征雷达图（Spider Chart）
- 历史趋势折线图（多次分析的 5 维度评分变化）
- 区域问题标注（在热力图上用箭头/文字标注具体问题）

### 7.5 增加异常检测

利用 n-sigma 规则或局部离群因子（LOF）检测异常分析结果。当一次分析与历史数据的偏差超过阈值时，提示用户"本次分析结果与以往差异较大，建议重新拍摄或确认光线条件"。

### 7.6 本地模型替代

将 Gemini Vision 替换为**本地部署的轻量模型**（如 Florence-2、LLaVA），降低 API 依赖和网络延迟。ROI 特征提取已完全本地化，仅 NLG 环节依赖云端 API。

### 7.7 时序趋势分析

利用 `SkinAnalysis` 数据库中的历史记录，构建**肤质变化时间序列**，通过滑动平均和线性回归生成趋势线，实现真正的"肤质趋势跟踪"而非仅报告当前状态。

# Mirror Mate v1 产品边界与重构路线图

本文档用于约束 Mirror Mate 接下来的产品设计、代码重构和 AI 辅助开发范围。后续改功能前，先用这份文档判断：这个功能是否属于 v1、应该放在哪个页面、数据从哪里来、是否会扩大技术债。

## 1. 当前真实架构

当前项目是前后端分离应用：

- 前端：`frontend/`，React + Vite + React Router。
- 后端：`backend/`，Flask + SQLAlchemy。
- 数据库：本地 SQLite 为主，支持按匿名用户 ID 隔离数据。
- AI 能力：Gemini 产品识别、语音识别、肤况建议生成；MediaPipe 做面部特征点检测；本地规则做 ROI 肤况特征提取和三庭五眼比例分析。

当前前端路由：

| 页面 | 路由 | 当前真实定位 |
|---|---|---|
| 今日页 | `/` | 今日入口页，包含天气、镜前建议入口、教程入口、产品记录入口 |
| 教程页 | `/tutorial` | 时间/场景筛选 + 三庭五眼拍照分析 + 生成抖音/小红书搜索词 |
| 产品页 | `/products` | 产品柜、官方产品库、拍照识别、语音录入、手动录入、分类、用量和到期信息 |
| 日记页 | `/diary` | 日历热力图、按日期看日记、创建日记、关联产品和镜前分析 |
| 日记详情 | `/diary/:id` | 查看单篇日记 |
| 我的页 | `/profile` | 肤质偏好、头像、产品提醒、主题、本地身份和数据导出 |

当前后端核心数据模型：

| 模型 | 作用 |
|---|---|
| `Product` | 用户产品柜 + 官方产品库。通过 `source=knowledge_base` 区分官方整理库 |
| `SkinAnalysis` | 镜前肤况分析记录，包含肤质、分区评分、镜前建议、热力图、趋势信息 |
| `Diary` | 美妆/护肤日记，可关联产品和一次镜前分析 |

当前真实能力闭环：

```text
拍脸 -> 肤况分析 -> 镜前建议 -> 可保存到日记
添加产品 -> 产品柜 -> 可被镜前建议和教程页读取
教程页拍正脸 -> 三庭五眼分析 -> 生成视频搜索词 -> 跳转外部平台
日记 -> 关联产品和镜前分析 -> 沉淀记录
我的页 -> 设置肤质/提醒/主题/本地身份
```

当前还没有形成的能力：

- 没有真正的教程内容库。
- 没有教程记录表。
- 没有教程和日记的正式关联。
- 没有真正的扫码/条码识别链路。
- 没有把抖音/小红书视频导入到站内播放。
- 我的页肤质偏好还没有系统性反哺推荐主链路。
- 首页后端 `/api/dashboard` 已存在，但当前首页主要是入口页，并没有完整使用 Dashboard 统计数据。

## 2. v1 产品定位

Mirror Mate v1 的定位：

```text
一个从镜前状态出发，帮助用户获得今日美妆/护肤建议、找到合适教程方向、管理已有产品，并沉淀日记记录的个人美妆助手。
```

v1 不做泛美妆社区，不做内容搬运平台，不做医学诊断，不做电商商城。

核心用户任务：

1. 我现在照镜子，不知道今天皮肤和妆前状态该怎么处理。
2. 我想快速找到适合当前场景的化妆教程方向。
3. 我想知道手头已有产品能不能用上。
4. 我想把今天的状态、产品和妆容记录下来。

## 3. v1 主链路

v1 只优先打通一条主链路：

```text
今日页拍照检测
-> 得到 1-3 条镜前建议
-> 去教程页看推荐方向
-> 匹配已有产品
-> 保存/补充日记
-> 我的页调整偏好
```

这条链路之外的功能都要降级处理，避免继续堆功能。

## 4. v1 功能边界

### 4.1 必须保留

- 今日页：拍照生成镜前建议。
- 今日页：展示今日入口，不再塞过多统计和复杂组件。
- 教程页：不检测也能看推荐方向；检测后推荐更个性化。
- 教程页：保留三庭五眼分析，但从主入口降为增强能力。
- 产品页：产品库搜索、一键加入产品柜。
- 产品页：拍照识别、语音录入、手动录入。
- 产品页：基础编辑、分类、用量、到期信息。
- 日记页：按日期创建和查看日记。
- 日记页：关联产品和镜前分析。
- 我的页：肤质偏好、提醒、主题、本地身份、数据导出。

### 4.2 暂时不做

- 不做站内视频导入。
- 不做自动抓取抖音/小红书视频、封面、文案。
- 不做完整社区、关注、评论、点赞。
- 不做商城、支付、购物车。
- 不做医学级诊断或治疗建议。
- 不做复杂的用户账号系统，v1 继续使用匿名本地身份。
- 不继续扩展主题/装饰功能，除非 UI 重构需要。
- 不优先做扫码，除非产品库、拍照识别和手动录入已经稳定。

### 4.3 可以作为 v1.1

- 用户手动收藏教程链接。
- 给教程链接添加备注和标签。
- 日记关联一个教程方向或教程链接。
- 我的页偏好真正影响教程推荐和镜前建议。
- 产品推荐更明确地使用 `suitable_skin`、`suitable_scenes`、`usage_steps`。

## 5. 页面职责边界

### 今日页

定位：今日镜前入口。

应该做：

- 展示今天日期、天气或简单环境信息。
- 主按钮：开始镜前建议。
- 展示最近一次镜前状态摘要。
- 提供去教程页、产品页、日记页的轻入口。
- 支持分析完成后保存到日记。

不应该做：

- 不管理完整产品柜。
- 不展示复杂历史统计。
- 不承载教程筛选逻辑。
- 不把所有功能都塞成首页卡片。

### 教程页

定位：教程方向推荐，不是视频搬运库。

应该做：

- 默认允许用户不拍照，直接按状态、场景、目标找教程方向。
- 检测后，用三庭五眼和比例标签增强推荐。
- 展示推荐搜索词和外部平台打开按钮。
- 读取产品柜，提示“你已有这些产品可用”。

不应该做：

- 不强制用户拍照才能看教程。
- 不把三庭五眼作为唯一入口。
- 不导入或下载平台视频。
- 不承诺教程来自官方授权视频库，除非后续真的接入。

推荐维度：

| 维度 | v1 建议 |
|---|---|
| 当前状态 | 没精神、底妆不服帖、眼睛肿、唇周暗沉、T 区出油 |
| 应用场景 | 上班/上课、面试、约会、拍照、晚间活动 |
| 妆容目标 | 干净自然、提气色、显眼大、显脸小、遮瑕修饰 |
| 时间预算 | 5 分钟救急、15 分钟日常、30 分钟完整 |
| 增强分析 | 三庭五眼、眼距、脸长宽、上中下庭 |

### 产品页

定位：我的产品柜。

应该做：

- 搜索官方整理库并加入产品柜。
- 拍照识别产品包装。
- 语音或手动录入产品。
- 编辑品牌、名称、分类、色号、规格、日期、价格、用量。
- 提供推荐标签：适合肤质、适合场景、适合步骤、适合区域。

不应该做：

- 不做商城。
- 不做大量购物链接堆叠。
- 不让产品页承担教程推荐主流程。
- 不让产品库数据和用户产品数据混在同一个 UI 语义里。

### 日记页

定位：记录今天的妆容、肤况、产品使用和感受。

应该做：

- 按日期看记录。
- 创建文字、拍照或相册日记。
- 关联今日使用产品。
- 关联今日镜前分析。
- 后续可关联教程方向或教程链接。

不应该做：

- 不做社交动态。
- 不做复杂内容编辑器。
- 不把日记变成另一个分析页。

### 我的页

定位：偏好、提醒、隐私和本地数据管理。

应该做：

- 设置肤质偏好。
- 设置提醒阈值。
- 管理头像和主题。
- 查看本地身份。
- 导出数据。

不应该做：

- 不放核心业务流程。
- 不新增和主链路无关的个性化装饰。
- 不让偏好只停留在展示层，后续要真实影响推荐。

## 6. 数据边界

### Product

`Product` 负责产品信息和产品推荐标签。它可以被：

- 产品页管理。
- 镜前建议读取。
- 教程页读取。
- 日记关联。

它不负责：

- 教程内容。
- 用户偏好。
- 日记正文。

### SkinAnalysis

`SkinAnalysis` 负责一次镜前检测结果。它可以被：

- 今日页创建和展示。
- 日记关联。
- 后续推荐逻辑读取。

它不负责：

- 存储三庭五眼教程推荐结果。
- 存储用户长期偏好。
- 存储医学结论。

### Diary

`Diary` 负责用户记录。它可以关联：

- 多个产品。
- 一次镜前分析。
- 后续一个教程方向或教程链接。

它不负责：

- 反向修改产品数据。
- 重新计算肤况分析。
- 承载推荐算法。

### User Preference

当前主要存在 `localStorage`，包括：

- 匿名用户 ID。
- 肤质偏好。
- 头像。
- 主题。
- 提醒设置。

v1 可以继续使用 `localStorage`，但推荐逻辑读取偏好时要集中封装，不要每个页面自己随便读。

## 7. 推荐边界

v1 推荐系统只输出“建议方向”，不输出绝对结论。

输入可以包括：

- 今日肤况分析。
- 面部比例分析。
- 用户肤质偏好。
- 用户选择的场景、状态、目标、时间预算。
- 产品柜中的产品标签。

输出应该包括：

- 1-3 条镜前即时建议。
- 教程搜索词或教程方向。
- 可用产品提示。
- 保存到日记的摘要。

不能输出：

- 医学诊断。
- 夸张功效承诺。
- 未授权视频内容。
- “必须购买某产品”之类的强商业导向。

## 8. AI 写代码边界

后续让 AI 改代码时，建议明确给它这些约束：

- 一次只改一个页面或一个能力。
- 不允许顺手重写全局样式。
- 不允许未经确认新增大功能。
- 不允许新增后端字段但不写迁移兼容。
- 不允许改变已有 API 返回结构，除非同步改前端调用。
- 不允许把抖音/小红书内容抓到本地。
- 不允许在页面里继续堆大量业务函数，复杂逻辑要移到 `utils` 或模块组件。
- 不允许删除已有用户数据兼容逻辑。
- CSS 修改必须遵守 `docs/frontend-css-boundary.md`。

推荐的提示词边界：

```text
请只修改 [页面/模块名]，目标是 [明确目标]。
不要新增无关功能。
不要改后端接口，除非我明确要求。
不要重写全局 CSS。
如果发现需要跨模块改动，先列出来，不要直接动。
改完后说明改了哪些文件、怎么验证。
```

## 9. 重构策略

总体策略：

```text
后端保留核心能力，前端按页面边界重整。
不要整项目推倒重写，也不要继续在现有大文件里堆逻辑。
```

原因：

- 后端的产品、肤况、日记能力已经有价值。
- 真正混乱的是前端页面职责、UI 风格、文件体积和功能入口。
- 完全重写会丢失现有接口、识别流程、数据库兼容和已完成能力。

## 10. 推荐目录方向

当前大文件建议逐步拆分，不一次性大爆炸。

目标结构：

```text
frontend/src/
  pages/
    Today.jsx
    Tutorial.jsx
    ProductManage.jsx
    MakeupDiary.jsx
    DiaryDetail.jsx
    Profile.jsx
  components/
    common/
    skin/
    tutorial/
    product/
    diary/
    profile/
  utils/
    recommendations/
    productCatalog.js
    skinAnalysisView.js
    themeSettings.js
    backgroundSettings.js
```

迁移原则：

- 页面文件只保留页面编排和少量状态。
- 可复用 UI 放 `components/common`。
- 业务组件按领域拆分。
- 推荐计算放 `utils/recommendations`。
- 不先移动后端，除非前端重构稳定。

## 11. 分阶段路线图

### Phase 0：基线确认

目标：知道当前能跑什么、哪里坏。

任务：

- 跑 `frontend` 构建。
- 跑后端基础接口。
- 记录当前 5 个页面主要坏点。
- 截图留当前 UI 状态。

验收：

- 有一份“当前问题清单”。
- 知道哪些是产品问题，哪些是代码问题。

### Phase 1：产品边界冻结

目标：停止发散。

任务：

- 以本文档为 v1 边界。
- 确认五个 Tab 名称和职责。
- 确认教程页不做视频导入。
- 确认扫码先不进 v1。

验收：

- 新功能需求都能归类为 v1 / v1.1 / 暂不做。

### Phase 2：视觉系统收口

目标：先让 UI 有统一基调。

任务：

- 统一底部 Tab、按钮、弹窗、卡片、输入框。
- 保留现有插画资产，但减少页面装饰堆叠。
- 优先整理公共样式，不做大范围视觉实验。

验收：

- 五个页面看起来像同一个产品。
- 移动端没有明显遮挡、溢出和重叠。

### Phase 3：今日页重整

目标：把首页从“入口堆叠”改成“今日镜前入口”。

任务：

- 将 `Dashboard.jsx` 逐步重命名或迁移为 `Today.jsx`。
- 保留镜前建议主按钮。
- 展示最近一次镜前分析摘要。
- 保留教程、产品、日记轻入口。
- 移除或折叠不必要的首页功能。

验收：

- 用户打开首页能立刻理解：这里是今天镜前建议。
- 拍照分析、查看结果、保存日记链路可用。

### Phase 4：教程页重构

目标：让教程页不依赖拍照也可用。

任务：

- 默认展示“状态/场景/目标/时间预算”筛选。
- 三庭五眼分析作为“增强推荐”模块。
- 无检测时也生成教程方向。
- 有检测时把比例标签加入搜索词。
- 继续只跳转外部平台，不导入视频。

验收：

- 不拍照也能看到推荐方向。
- 拍照后推荐更个性化。
- 页面文案不再暗示站内有视频库。

### Phase 5：产品页瘦身

目标：保留强能力，拆掉大文件压力。

任务：

- 把产品列表、详情、产品库弹窗、产品提醒拆成独立组件。
- 保持现有 API 不变。
- 明确“官方产品库”和“我的产品柜”的 UI 差异。
- 确认添加路径：产品库搜索优先，拍照/语音/手动作为补充。

验收：

- 添加、编辑、删除、搜索、分类、用量可用。
- 页面文件复杂度下降。

### Phase 6：日记闭环

目标：让日记成为主链路的沉淀层。

任务：

- 保留按日期记录。
- 优化从镜前分析保存到日记。
- 日记表单中清晰展示关联产品和关联镜前状态。
- 后续增加“教程方向/教程链接”关联字段或本地记录。

验收：

- 用户能从今天检测结果自然生成一篇日记。
- 日记详情能看懂当天用了什么产品、有什么状态。

### Phase 7：我的页偏好生效

目标：偏好不再只是展示。

任务：

- 统一读取肤质偏好的工具函数。
- 教程推荐读取肤质偏好。
- 产品库筛选可读取肤质偏好。
- 镜前建议提示中可以参考偏好，但不覆盖检测结果。

验收：

- 用户设置肤质后，教程页和产品推荐有可见变化。

### Phase 8：清理和验证

目标：减少技术债。

任务：

- 删除确认废弃的 CSS 和组件。
- 补充最小测试或手动验证清单。
- 更新 README，避免文档写了不存在的能力。

验收：

- `npm run build` 通过。
- 后端核心接口可用。
- README 与真实功能一致。

## 12. 每页验收清单

### 今日页

- 能打开页面。
- 能打开镜前建议弹窗。
- 能拍照或选择照片。

- 能查看历史镜前记录。

- 不拍照也能生成推荐搜索词。
- 拍照后能完成三庭五眼分析。
- 拍照后搜索词加入比例标签。
- 能打开抖音/小红书搜索页面。

### 产品页

- 能从官方产品库搜索并加入。
- 能拍照识别。
- 能语音录入。
- 能手动新增。
- 能编辑和删除。
- 能记录用量和到期信息。

### 日记页

- 能选择日期。
- 能创建日记。
- 能上传照片。
- 能关联产品。
- 能关联当天镜前分析。
- 能进入详情页。

### 我的页

- 能设置肤质偏好。
- 能设置提醒。
- 能改主题。
- 能导出数据。
- 能查看和重置本地身份。

## 13. 当前优先级

最高优先级：

1. 先确认当前功能哪里跑不通。
